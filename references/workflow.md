# AI 接管执行流程

用户准备登录态和授权，Agent 负责核实、备份、配置与验收；安全输入和不可控设备才交由用户短暂接手。宿主权限规则始终优先。

## 0. 能力、目标与断点

先读 [preflight.md](preflight.md)。使用宿主工具发现已打开的页面和应用，只读请求不进入写入步骤。不要硬编码截图索引、坐标或内部工具名。

在仓库外私有目录维护阶段记录：目标、授权范围、备份路径、计划哈希、已执行副作用和验证结果。不记录凭据或完整聊天。超时/中断后先查目标端状态，确认是否已执行，再决定恢复，不盲重试。

## 1. 基线、备份与备用线路

核对正确服务、3X-UI 与原入站；区分朋友的备用节点。通过实际进程或受支持界面确定 Mihomo 的控制入口，不能把示例 socket 当真实路径，更不能公开控制器。

备份面板支持的配置、必要网络/防火墙状态、本地 Profile 与组选择。数据库备份须一致，禁止直接改库。备份包含敏感信息，留在私有目录。

正常 API 认证可用时优先受支持接口；没有时使用真实 UI。不提取 Cookie、不绕过登录、不创建不必要的持久管理 Token。服务中断前先切换获授权的备用线路并实测联网。

## 2. VPS IPv6

先看内部地址和路由，避免重复配置。KiwiVM 明确要求时：正常关机 → 读取 `Stopped` → 启动 → 等 SSH/面板恢复。会话过期通过正常 SSO 重新进入，必要时请用户登录；不自动解决验证码。

恢复后核实实际地址属于子网、默认路由、IPv6 出站、本机到目标端口和开机持久配置。面板显示 `/64` 不等于节点可用；6in4 不是独立 IPv4 故障域。

## 3. VLESS Reality 的 IPv6 入口

检查原服务实际是否双栈。配置出现 `0.0.0.0` 也不能代替真实 IPv6 连接测试。已可连接就不改原入站；确有必要时只改授权的监听或防火墙项。

保留原 UUID、Flow、SNI、Reality 密钥、Short ID 与 TCP 端口。从原节点复制字段，只改新节点名称和实际 IPv6 主机地址。先在仅本机监听、不接管 TUN、不抢现有端口的隔离进程里测试握手和请求。

## 4. 新增独立 HY2

1. 回读现有资源，按协议、端口、备注和客户端关系去重；冲突停止，不重复创建。
2. 确认版本、UDP 端口、双栈监听、证书能力和防火墙。
3. 创建独立证书/私钥或配置有效证书；私钥留服务器，客户端只需公开验证材料。
4. 新入站先停用，配置版本 2、TLS、`h3`、独立客户端并关联，再启用。
5. 不默认开启端口跳跃或混淆。遇已核实的默认项兼容问题，按证据选择最小配置，不擅自升级。
6. 保存后回读面板和运行状态，确认原节点仍正常、新 UDP 监听和认证关系正确。

[3X-UI 官方文档](https://docs.sanaei.dev/docs/config/inbounds/)说明协议与入站结构；实际 UI/API 版本需现场核实。未知版本不能反复猜接口或改数据库。

## 5. 证书校验对照

指纹由可信管理通道取得。Mihomo `fingerprint` 为证书指纹，`client-fingerprint` 为另一功能；不要混填。见 [Mihomo TLS 文档](https://wiki.metacubex.one/config/proxies/tls/)。

正确配置成功后，在隔离测试副本中换成错误指纹，确认明确拒绝，再恢复正确配置复测。错误指纹也成功必须停止。原节点、VLESS IPv6、HY2 IPv4、HY2 IPv6 分别验证；不让隔离测试改变日常选择。

## 6. 增量修改本地 Profile

先读取实际脚本 `--help`。本地典型步骤：

```text
inspect --profile <明确选中的 Profile>
prepare --profile <同一文件> --nodes <私有节点 JSON> --state-dir <新的私有状态目录>
apply --plan <生成的 plan.json> --approve
```

节点 JSON 使用 `base_node`、`nodes`、`groups`：基础节点是已核实的现有节点名，`nodes` 是完整已验证节点对象数组，`groups` 是明确需增加选项的选择器名。凭据留私有文件，不贴聊天。

准备阶段只生成备份、候选和哈希计划；应用前检查源文件未漂移，确认具体路径与动作已授权。同名同配置可跳过，同名不同配置、缺基础节点或目标组冲突停止。YAML 锚点/别名、重复键和仅 provider 的配置等未支持形状拒绝处理。

原节点、规则和 DNS 保留。添加字面 IPv6 节点时只在必要范围启用全局 IPv6；DNS 的 IPv6 开关独立保留。通过 Clash 重新激活正确订阅，再回读运行内核；检查 GUI 全局设置是否覆盖源 YAML。

## 7. 统一切换代理组

保持规则模式。组选择彼此独立，默认不配置后台自动故障切换。

先读取全部目标组，确认存在、类型支持且包含目标节点，保存原选择，再逐组执行：

```text
switch --socket <实际 Unix socket> --node Main-HY2-IPv4 --groups Proxy ClaudeProxy OpenAIProxy --approve
```

失败时尝试恢复已改组，并回读每组最终状态；不能把多次 API 操作称为原子事务。既有长连接可能继续用旧线路，检查新建连接。任务结束恢复约定的默认选择。

## 8. 实际验收

每节点至少三次请求，记录当前 Profile、组和实际节点。证据分层：

| 检查 | 不能替代的下一层证据 |
| --- | --- |
| 监听与端口 | 不能证明 Reality/HY2 认证 |
| 显式 loopback 代理请求 | 不能证明 TUN 接管 |
| 排除环境代理的请求 | 仍需路由、运行配置、规则与连接链佐证 |
| 页面外壳或 HTTP 响应 | 不能证明视频播放或聊天生成 |

`verify --proxy http://127.0.0.1:<实际端口>` 检查本地代理；不传 `--proxy` 则用 `--noproxy '*'` 排除环境代理。报告保留 `node_routing_verified=false`、`browser_acceptance=not-run`，Agent 须补实际连接链和浏览器证据。

Google 204、YouTube 200 如实记录。ChatGPT 403、验证码、脚本错误或持续加载单列，不能当作通过。不得为过验收清 Cookie、关闭校验或自动解验证码。浏览器能打开也不代表已测试聊天生成。

## 9. 导出、收尾与回滚

```text
mobile --profile <明确文件> --output-dir <新的私有目录> --names <需要导出的节点名...>
```

输出 `nodes.txt`、`scan.html` 和 `node-N.svg`，全部离线生成。不得用在线二维码或订阅转换服务。HY2 链接保留 `insecure=0` 和固定 `pinSHA256`；客户端可能忽略字段，必须在手机核实导入指纹并实际测试，证书错误时停下，不盲开“允许不安全”。参阅 [HY2 URI 规范](https://v2.hysteria.network/docs/developers/URI-Scheme/)。

手机未控或用户要求稍后验收，明确“电脑已验收，手机待验收”。本机结果不代替 Mac mini/手机结果。

确认开机持久配置，停止临时进程，恢复默认选择并释放电脑控制。输出改动、逐节点结果、未验收项、私有文件路径和回滚方法，不打印凭据或完整链接。

本地 `rollback --plan <plan.json> --approve` 只在当前文件仍匹配本次结果时恢复。服务器回滚按本次资源清单及备份，经授权撤销新增项；不整库覆盖、不删除未知资源、不覆盖后续用户改动。
