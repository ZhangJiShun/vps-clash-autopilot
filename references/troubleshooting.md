# 按证据排查

先记录脱敏错误、当前阶段和已执行的副作用。每次修复要有具体假设和复现检查，不反复换端口、重建密钥、重启或升级。

| 现象 | 先查什么 | 不应直接推断 |
| --- | --- | --- |
| 延迟正常，网页打不开 | 实际 Profile、组选择、显式代理、TUN、规则与连接链 | “VPS 完全正常”或“宽带有问题” |
| 显式代理成功，TUN 超时 | 实际进程/接口、测试地址和 VPS 路由、内核是否收到请求、规则、其他 VPN/过滤器 | 存在 `utun` 就等于 TUN 正常 |
| 源 YAML 开启 IPv6，运行态关闭 | GUI 全局覆盖、生成层、重新激活正确订阅、内核 API | 改了文件就算生效 |
| VPS 有 IPv6，节点不能用 | 本地网络、主机地址/路由、监听、防火墙、隧道和握手 | 有 `/64` 就等于能连接 |
| 端口可连，Reality 认证失败 | 实际加载字段、同入站公钥/Short ID/SNI、目标握手和相关服务端日志 | TCP 成功即认证成功；盲目生成新密钥 |
| HY2 不通 | UDP 路径、版本、认证客户端、ALPN、证书/指纹、监听及启用状态 | TCP 测试能证明 UDP 可达 |
| 错误指纹也能用 | 导出/导入是否丢字段、客户端支持、实际运行配置 | 跳过校验也算修好 |
| Proxy 换了，AI 仍不通 | 独立 AI 组选择及新旧连接链 | 所有组会跟随 Proxy |
| KiwiVM/创建请求超时 | 目标任务状态、会话过期、正常 SSO、回读资源列表 | 超时等于失败，应立即重发 |
| ChatGPT 403 或一直加载 | 站点响应、验证页、页面脚本和实际 AI 连接链 | 必然是 VPS 无网，或页面外壳代表完整成功 |
| 手机不通，电脑正常 | 手机实际字段、所用配置/组、证书指纹、Wi-Fi/蜂窝分别测试 | 电脑通过代表手机通过 |

## 控制入口或设备找错

从实际运行进程或受支持界面发现 socket，不猜路径，不把示例端口当当前端口。脚本只使用显式本地 Unix socket；不可用时通过宿主 UI 检查，不开放控制器或提取 Cookie 补认证。

只共享鼠标无法证明 Agent 可看见另一屏。需实际授权的屏幕共享/远程控制或在目标机器运行 Agent，不能用本机命令冒充远端结果。

## 配置漂移与重复运行

- 计划后用户改了 Profile：停止应用，重新读取、生成计划。
- 应用后用户又改配置：停止回滚，先展示差异，不覆盖新工作。
- 同名节点参数不同：冲突，不覆盖；不同名称也不代表一定要新建服务端资源。
- 面板保存超时：先回读列表和运行状态，不能直接再点“创建”。
- 备份失踪或计划哈希不匹配：停止写入，不能关闭检查继续。

## 不支持的形状或版本

YAML 锚点/别名、重复键、仅 provider 的配置由辅助脚本明确拒绝。不要手工删掉这些结构来让校验通过；报告支持边界，先给出独立、可审阅的配置方案。

核实面板/内核版本、官方说明和日志。缺功能时完成独立步骤，说明升级或独立部署的具体取舍；升级另行确认。不下载不明脚本，不改库伪造兼容字段，不反复猜 API。

## 部分切换或回滚失败

区分“切换失败”和“恢复原选择也失败”。记录各组原值、尝试值和最终回读；不能把部分成功说成全部成功。保留备份并明确当前状态；服务器也不能整库恢复覆盖后续改动。

## 必须用户接手时

只问当前阻塞必需的信息并说明原因：验证码本人完成、管理员密码只能本地输入、另一设备不在控制范围等。其余能由 Agent 检查的继续处理，不把整份排查清单推回用户。
